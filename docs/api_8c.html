Detailed Description

Runtime framebuffer text console with UTF-8 and ANSI/CSI support.

Maintains an in-RAM cell grid, blits glyphs via the compiled-in CP437 bitmap or a userspace-supplied Fira atlas, and renders scrollback history. Takes over the framebuffer from the early boot logger once kmalloc is up.

DECCKM state. When true the keyboard layer emits SS3 (\EOA) for cursor keys instead of CSI (\E[A). Toggled by ncurses keypad().

◆ fb_console_fill_winsize()

void fb_console_fill_winsize ( k_winsize_t *  out)

Pack live console geometry into a Linux winsize for a TIOCGWINSZ answer.

Fill out with the live grid dimensions, packaged as a Linux winsize struct ready to be copied to userspace by a TIOCGWINSZ handler.

Pre-seeded with the VT100 fallback and re-clamped after the query because fb_console_get_size returns the raw ctx fields without sanitising — if a TTY ioctl ever races the boot path before fb_console_init runs we still hand userspace something a TUI can divide by.

Pixel dimensions are zeroed: the grid is a character matrix, no caller has a use for the underlying pixel span and reporting a wrong value would mislead TUIs into laying out against a non-existent geometry.

Parameters
outDestination winsize. Caller-owned, no NULL guard (a kernel caller passing NULL is a logic bug — fail fast via crash).

Bring the framebuffer console online and allocate its cell grid.

Initialise the runtime console using the same framebuffer the boot logger has been writing to. Allocates the cell grid via kmalloc, so call after heap init.

Sized to fill the framebuffer with the bitmap font (8x16); the grid is resized once a userspace atlas registers a different cell size. Margins stay zero on this path so boot output uses every pixel — the margin is an atlas-era cosmetic, not a fundamental layout property.

Parameters

widthFramebuffer width in pixels.
heightFramebuffer height in pixels.

bppBits per pixel; normalised to 1/2/3/4 bytes-per-pixel.
Returns
true on success, false if the cell grid kmalloc failed (in which case every subsequent fb_console_* call no-ops).

Push one byte from the keyboard IRQ into the read ring.

Read one input byte from the keyboard layer into the console's input ring. Called from the keyboard IRQ. Plain pass-through queueing — the kernel keyboard already handles line discipline + layout translation.

Drops on overflow rather than blocking: the IRQ path must not stall. The blink phase is forced visible so the cursor stays solid while the user is actively typing (visible-cursor lag while typing is a known UX problem with raw blink).

Parameters
byteByte produced by the keyboard layer (UTF-8 / xterm seq).

void fb_console_tick ( void  )

PIT tick callback: advance blink phase and reposition the mouse cursor.

Tick the cursor blink phase. Called from the PIT IRQ (100 Hz).

Two concerns share the tick because both want the same cadence: caret blink at the configured rate, mouse cursor smoothness as fast as the tick itself. The blink branch repaints FB_ATTR_BLINK cells in one batched flush so the screen doesn't flicker; mouse render early-outs when the pointer hasn't moved, so it's free at rest.

◆ fb_console_yield()

void fb_console_yield ( void  )

Hand the framebuffer to a userspace mmap-er (typically Doom).

Yield the framebuffer to a userspace process for raw pixel access (games, graphics demos). The kernel stops rendering until fb_console_reclaim is called.

Subsequent writes from the kernel are no-oped (yielded gate) so the user-program's pixels survive. The mouse cursor is dropped so the next fb_console_reclaim repaints a fresh arrow rather than trying to XOR-erase a position whose underlying pixels have been replaced.
