sigaction sa_flags

The full Linux x86_64 set is exposed so musl's rt_sigaction wire layout is preserved across the syscall boundary. Today the delivery path (proc_check_signals) only consults SA_NODEFER and SA_RESETHAND; the others are accepted into k_sigaction_t but otherwise inert.

Detailed Description

POSIX signal handling infrastructure (Linux x86_64 compatible).

Implements a signal subsystem sufficient to run programs that rely on signal delivery (for Clang/LLVM).

void proc_check_signals ( void *  frame)

Check for deliverable signals and set up signal frame if needed.

Called from syscall_entry (ASM) after syscall_dispatch returns. May redirect the syscall frame to a signal handler by modifying frame->rip, frame->rsp, and frame->rdi.

Parameters
framePointer to the syscall_frame_t on the kernel stack.

Check for deliverable signals and set up signal frame if needed.

Called from syscall_entry (ASM) after syscall_dispatch returns, before restoring user registers. May modify the syscall frame to redirect execution to a signal handler.

Delivery layout on user stack (grows down):

[new RSP] → sa_restorer address (return address for the handler)
[new RSP + 8] → sig_ucontext_t (saved context for rt_sigreturn)
