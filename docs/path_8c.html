Detailed Description

Path resolution, symlink following, and the ext2_stat / ext2_readlink endpoints.

Walks a path component-by-component, following symlinks with a recursion depth cap to bound runaway loops. Symlink-target reading covers both fast symlinks (target inline in i_block[]) and slow symlinks (target stored in the first data block); centralising both in one helper keeps the fast/slow choice in one place.

◆ EXT2_FAST_SYMLINK_MAX

#define EXT2_FAST_SYMLINK_MAX   60u

Inline-storage capacity for fast symlinks.

ext2 stores the i_block[] array as 15 × u32; targets up to 60 bytes fit inline and skip the data-block round trip.

◆ SYMLINK_BASE_RESERVE_BYTES

#define SYMLINK_BASE_RESERVE_BYTES   8u

Spare bytes reserved when growing base_for_link in follow_symlink_step.

The dummy filename appended before build_symlink_path is "/X\0" (3 bytes); 8 is a conservative ceiling that survives future tweaks to the dummy without recomputing the bound.

◆ SYMLINK_MAX_FOLLOW

#define SYMLINK_MAX_FOLLOW   8

Maximum symlink chase depth before declaring -ELOOP.

Same constant Linux uses. Far above any sane userland chain, low enough to keep the recursive resolve_path_depth from blowing the kernel stack on a hand-crafted symlink cycle.

Read the target of the symlink at path into buf.

Read symlink target (final path component only). Path is mount-relative (e.g. "bin/clang"), no leading slash.

Splits the path so the target's containing directory is resolved (not the symlink itself — that would follow it). The final component is then looked up directly, its inode validated as a symlink, and the target read via the shared read_symlink_target so fast/slow link layouts stay in one place.

Parameters
volVolume handle.
pathAbsolute path of the symlink.
bufOutput buffer (no terminating NUL appended).
capCapacity of buf.
Returns
Bytes written, or negative errno (-EINVAL for non-symlinks, -ENAMETOOLONG when the target exceeds cap).
