Detailed Description

ANSI/CSI escape parser, UTF-8 decoder, and SGR/colour resolution for the framebuffer console.

The entry point feed_byte is the state machine: bytes coming from fb_console_write_raw pass through the ANSI ESC/CSI / G0-charset states before falling through to UTF-8 decoding and finally put_cp_at_cursor. SGR colour handling lives next to the parser because ansi16_fg / ansi256_to_rgb are referenced only here.

Translate a DEC ACS (Special Graphics) printable ASCII byte to its Unicode equivalent.

Active only while ESC ( 0 has selected G0=ACS. The kernel's CP437 bitmap lacks most of these glyphs; the userspace atlas provides them when loaded. Unrecognised bytes pass through unchanged so ncurses falling back to ACS still draws plain text where a translation isn't defined.

Parameters
bInput byte in the printable ASCII range.
Returns
Translated codepoint, or b unchanged when no mapping exists.

Handle one byte while the parser is in the ESC-was-just-seen state.

Recognises the next byte's role (CSI introducer, DEC save/restore, charset designator) and transitions or commits accordingly. Unrecognised bytes drop back to normal so a stray escape (DECKPAM =, DECKPNM >, etc.) does not poison subsequent output.

◆ feed_utf8()

static void feed_utf8 ( u8  b)
static

Stream one byte through the UTF-8 decoder; emit a codepoint when a sequence completes.

Self-restarting on broken sequences (stray continuation, invalid lead): emits a ? and replays the offending byte fresh. This keeps a corrupt input stream from desyncing the parser forever, at the cost of one placeholder glyph. ANSI/CSI sequences are stripped upstream by feed_byte so this only ever sees printable / control bytes.

bInput byte.
