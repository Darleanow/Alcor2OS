ext2_file_t g_files [EXT2_MAX_FILES]
 Open-file pool. Sized at EXT2_MAX_FILES to cover a typical shell session plus background daemons without ever evicting a handle.
 

Detailed Description

File open / close / read / write / truncate / flush — the public ext2 byte-oriented API.

Owns the open-file pool (g_files) and bridges between the public ext2_* API and the block-mapping / inode helpers in the rest of the module. The read / write loops delegate one-iteration chunks to small helpers so the public functions read as a control flow instead of as three nested concerns at once.

Truncate an ext2 file to length bytes.

Truncate a file to zero length.

If shrinking past zero, free all data blocks; if extending, simply record the new size — ext2_read returns zeros for unallocated holes, matching POSIX sparse-file semantics.
