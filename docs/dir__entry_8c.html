Detailed Description

On-disk directory entry primitives — lookup, insert, remove, emptiness check.

The on-disk directory format is a sequence of variable-length records inside the directory's data blocks; every helper here walks that structure with the same offset / rec_len arithmetic. Kept in one file so the dirent layout knowledge stays in a single place and the higher- level ops in dir.c only depend on the typed interface (find / add / remove / is_empty), never on rec_len byte math.

The per-block scanners (dir_block_find_name, dir_block_remove_name, dir_block_count_entries, dir_block_try_insert) own the inner dirent walk; the public functions just iterate the directory's data blocks and delegate.

#define EXT2_DIRENT_ALIGN   4u

Byte alignment for an on-disk ext2_dirent_t record.

ext2 stores dirents at 4-byte boundaries; rec_len is rounded up to the next multiple. Named so the rounding math reads as alignment, not as the literal 4 it derives from.

Add a directory entry.

Insert a new entry into dir_inode (creating a new data block if no existing block has room).

Two-phase: try dir_try_insert_into_existing first; on -ENOENT, fall through to dir_grow_with_entry. The scratch buffer is owned here so both helpers reuse the same allocation.

Try to insert a new dirent into a single block by splicing slack.

ext2 packs dirents back-to-back with each carrying rec_len = "bytes until next dirent (or end of block)". Slack at the end of an existing dirent is reusable: shrink the predecessor's rec_len to its actual size and lay the new dirent in the recovered space.

Try to splice the new entry into any existing block's slack.

Sweep over every allocated block in the directory; on the first block with enough slack, dir_block_try_insert mutates it in place and we persist with vol_write_block. -ENOENT is the "nowhere to put it" sentinel that tells dir_add_entry to fall through to growth.
