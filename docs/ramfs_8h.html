Detailed Description

Public ramfs API: init + character-device registration.

Ramfs backs both the root fallback (when there is no disk) and the /dev mount. Drivers register character-device callbacks against a ramfs path; reads/writes/ioctls on that node are routed to the callback table instead of the in-memory byte buffer.

typedef struct ramfs_chardev_ops ramfs_chardev_ops_t

Driver-supplied callback table for a character device.

Any callback left NULL gets a sensible default from ramfs: read/write fail with -EINVAL, ioctl returns -ENOTTY, and poll reports "always ready" (so apps that don't care about backpressure aren't penalised).

Register a character device under path inside the ramfs tree.

path is rooted at the ramfs root (which the kernel mounts at /dev), so "/mouse" surfaces as /dev/mouse to userspace. Parent directories must exist. The registered node cannot be removed via unlink / rmdir.

Parameters
pathRamfs-relative path; must start with /.
opsCallback table (pointer must outlive the kernel; statics OK).
ctxOpaque pointer forwarded to each callback.
Returns
0 on success, negative -errno on failure.
